# 🚀 ПЛАН РАЗВИТИЯ TENBID v3.0 "TRUE MATRIX"

**Статус:** Утвержден к реализации  
**Принципы:** Никаких упрощений, никаких заглушек, полная готовность модулей к PR в main.  
**Цель:** Переход от консервативного HOLD к точному скальпингу во флэте и тренде за счет углубления анализа и синтеза данных.

---

## 📊 ТЕКУЩЕЕ СОСТОЯНИЕ (v2.0 Base)
- **Ядро:** Работает стабильно, синтез ТФ из 5m реализован (resample).
- **Данные:** Накоплено 206 циклов анализа, 194 снимка контекста, 1025 тестов Shadow Lab.
- **Проблема:** 100% решений HOLD. Средняя уверенность 0.48 при пороге 0.71.
- **Причина:** Недостаточная детализация (нет микроструктуры свечи), усредненный стакан, отсутствие кросс-валидации между анализаторами.
- **Ресурс:** База данных `TENBID/trade_history.db` содержит полный контекст для обучения Autotuner после внедрения изменений.

---

## 🗺️ ДОРОЖНАЯ КАРТА РЕАЛИЗАЦИИ

### ЭТАП 1: ФУНДАМЕНТ ДАННЫХ (Синтез и Структуры)
*Цель: Создать единое пространство прогнозов для кросс-валидации и выявления "горячих точек".*

1.  **Унификация структур данных (`models/forecast.py`)**
    -   Класс `Forecast`: `timestamp`, `tf`, `price_target`, `direction`, `confidence`, `horizon` (в свечах/мин), `analyzer_id`.
    -   Все анализаторы переходят на выдачу только этого объекта.
    -   *Статус:* Ожидает реализации.

2.  **Многомерная Матрица Прогнозов (`core/prediction_matrix.py`)**
    -   Хранилище ключей `(time_bucket, price_zone)`.
    -   Метод `add_forecast()`: накопление прогнозов от всех анализаторов.
    -   Метод `get_clusters()`: поиск зон пересечения ("горячие точки"), расчет `Consensus Score`.
    -   *Статус:* Ожидает реализации.

3.  **Движок Кросс-Валидации (`core/synthesis_engine.py`)**
    -   Выявление конфликтов (напр., Orderbook=SHORT vs Pattern=LONG).
    -   Логика весов в зависимости от горизонта сделки (краткосрок игнорирует долгосрочный тренд при сильном локальном импульсе).
    -   Формирование итогового сигнала с флагами `CONFLICT` или `CONFIRMED`.
    -   *Статус:* Ожидает реализации.

### ЭТАП 2: УГЛУБЛЕНИЕ АНАЛИЗА (Микроструктура и Стакан)
*Цель: Повысить разрешение системы для входа в микро-движения.*

4.  **Анализ микроструктуры свечи (`analyzers/microstructure.py`)**
    -   Функция `analyze_candle_internal()`: запрос 1m/тиков по конкретной 5m свече только при потенциальном сигнале (On-Demand).
    -   Детекция внутренних паттернов (пин-бары, ложные пробои).
    -   Возврат коэффициента `micro_quality_score`.
    -   *Статус:* Ожидает реализации.

5.  **Умный кэш стакана (`data/orderbook_cache.py`)**
    -   Адаптивное обновление: базовый интервал 5-10 сек + событийные триггеры (скачок цены/объема).
    -   История снимков для анализа динамики (стены, спуфинг, поглощение).
    -   Экономия API запросов при повышении информативности.
    -   *Статус:* Ожидает реализации.

### ЭТАП 3: МОДЕРНИЗАЦИЯ АНАЛИЗАТОРОВ
*Цель: Адаптировать модули под новую архитектуру.*

6.  **Переписывание анализаторов (полный цикл):**
    -   `btc_correlation`: мульти-ТФ корреляция в реальном времени.
    -   `fractal_analysis`: поиск уровней на синтезированных ТФ + микроструктура.
    -   `orderbook_analysis`: работа с кэшем и историей.
    -   `pattern_recognition`, `volume_analysis`, `market_regime`: вывод в формате `Forecast`.
    -   *Статус:* Ожидает реализации.

### ЭТАП 4: СТРАТЕГИЯ И ИСПОЛНЕНИЕ
*Цель: Принятие решений на основе консенсуса.*

7.  **Обновление Стратега (`core/strategy.py`)**
    -   Вход: кластеры `PredictionMatrix` + флаги `SynthesisEngine`.
    -   Логика: вход при `Consensus Score` > порога и отсутствии критических конфликтов.
    -   Динамический расчет SL/TP на основе плотности кластера.

8.  **Futures Execution Module (`core/futures_execution.py`)**
    -   Интеграция динамического плеча (старт 1x, эксперименты 2x).
    -   Умный трейлинг-стоп (активация после прохождения зоны безопасности, подтягивание по фракталам/ATR).
    -   Точное размещение ордеров на основе микроструктуры.

### ЭТАП 5: ОБУЧЕНИЕ И КОНТРОЛЬ
*Цель: Замкнуть цикл самообучения.*

9.  **Расширение снимков для Autotuner**
    -   Новые поля: `consensus_score`, `conflict_flag`, `micro_quality`, `orderbook_dynamic_score`.
    -   Обучение на основе качества синтеза, а не только отдельных сигналов.

10. **Визуализация и отладка**
    -   Вывод карты "горячих точек" матрицы в лог/дашборд.
    -   Мониторинг работы кэша стакана.

## 🛡️ ПРАВИЛА РАЗРАБОТКИ
1.  **Запрет на упрощение:** Любой новый функционал добавляется поверх существующего или заменяет его полностью, но не удаляет возможности.
2.  **Запрет на заглушки:** Модули пишутся целиком, готовыми к бою. Если модуль не готов — он не включается в ядро.
3.  **Согласование:** Любые изменения в логике риска, управления капиталом или архитектуре требуют явного подтверждения перед коммитом.
4.  **Честность данных:** Синтез таймфреймов строго математический. Микроструктура берется из реальных тиковых данных (или 1m свечей).
5.  **Надежность:** Приоритет отдается сохранению депозита. Плечо и агрессивность вводятся только после подтверждения статистикой.
